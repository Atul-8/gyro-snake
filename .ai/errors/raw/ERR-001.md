# ERR-001 — 触摸坐标按参考代码的 800x480 假设写了映射

- 日期：2026-11-23
- 模块：`firmware/components/touch_port`

## 1. 现象

为“点击右下角倾斜球归零”实现 GT911 坐标映射时，先按轴交换写了
`x = raw_y * 479 / max_y`、`y = raw_x * 799 / max_x`，并在注释里把它当成
“面板原生 800x480、UI 竖屏 480x800，所以必须交换”。代码写完、尚未上机验证。

## 2. 根因

依据是参考工程 `_ref_sticky/main/devices/sticky_touch.cpp` 里的
`kDisplayWidth = 800 / kDisplayHeight = 480`，以及 `gt911.cpp` 的
`begin(..., 800, 480, ...)`。但那是**参考工程的画布尺寸**，不是本机 GT911
`0x8146` 分辨率寄存器的实际返回值。烧录后启动日志给出：

```text
gs_touch: GT911 ready: address=0x14 id=911 res=480x800
```

传感器自报 480x800（竖屏），轴交换从一开始就是错的。

## 3. 修复

- `gt_probe()` 读取 `GT911_REG_COORD_RES (0x8146)`，把真实范围存进
  `s_max_x / s_max_y`，并在启动日志打印。
- `touch_map()` 改为同轴缩放（raw X → 屏幕 X，raw Y → 屏幕 Y），翻转留待实测。
- 每次按下打印 `tap raw=<rx>,<ry> -> screen=<sx>,<sy>`，用一次已知角落点击即可标定。
- 归零判定先接受“任意角落”，使四种翻转组合下都能工作，不阻塞功能验证。

## 4. 预防

- 任何触摸/显示坐标变换，先读设备自报参数（分辨率寄存器、启动日志），再写公式。
- 参考代码里的尺寸常量只当作“参考工程的配置”，不当作本机事实。
- 坐标类代码必须有可观测输出（raw + mapped），否则无法用一次点击证伪。
